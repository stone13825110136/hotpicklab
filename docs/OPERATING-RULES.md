# HotPick Lab — 站务与协作规则（Operating Rules）

**站点：** hotpicklab.com  
**适用范围：** 本仓库一切产品、内容、SEO、上线与 Cursor/人工协作  
**更新日期：** 2026-07-26  
**状态：** 已生效（2026-07-26 确认按 11 条执行）

> 本文是 **内部规范**，不部署为面向访客的页面。站点上只出现客户能看懂的产品与合规文案。

---

## 0. 一句话原则

**SEO 一开始就用专家模式一次做对；上线前专家全面测试；开源数据不闭门造车；站上只放客户内容；HotPickLab ≠ MiniTool。**

---

## 1. 你指定的硬规则（必须遵守）

### R1 — SEO 一律「SEO 专家模式」

凡涉及收录、标题、描述、URL、内链、sitemap、长尾页、IndexNow/站长工具提交，必须按专家标准执行，禁止「随便写个 title 就上」。

**专家模式最低清单：**

| 项 | 要求 |
|----|------|
| 意图 | 先写清用户搜索意图（信息/交易/工具），再写文案 |
| Title / H1 | 主关键词自然出现；不堆砌；品牌可放末尾 |
| Meta description | 有利益点 + 差异（Hot Pick / Compare），勿内部黑话 |
| URL | 短、英文、可读（如 `/tools/pet-name-lab`、`/dog-names/...`） |
| 索引 | 新页/大改后更新 sitemap；部署后 IndexNow 或站长提交重点 URL |
| 技术 | 无误 301 挡产品页；`robots` 允许抓取；Core Web Vitals 不因花哨动效崩盘 |
| 长尾 | 优先可排名长尾，不与巨头硬刚大词唯一首页 |

**禁止：** 中英混排内部备注进 meta；把「Phase 1」「MVP」「豆包说」写进公开 SEO 字段。

---

### R1b — 上线内容必须「一开始」就按 SEO 专家模式做好（一次做对）

**所有准备上线的页面/工具/文案，动笔或建页的第一步就是 SEO 专家模式，而不是先糊功能再回头改 SEO。**

目的：**避免反复改 title、H1、URL、骨架造成的返工、收录波动和工期浪费。**

| 阶段 | 必须先完成（再写大段正文/大改 UI） |
|------|-------------------------------------|
| 立项 | 目标关键词 / 搜索意图 / 页面类型（工具页 vs 长尾内容页） |
| 信息架构 | 最终 URL、H1、title、meta description 草案（专家标准） |
| 内链 | 从哪进、链到哪（首页 / Labs / 相关长尾） |
| 再开发 | 功能与正文围绕已定 SEO 骨架展开 |
| 上线 | R2 测试；非必要不改已收录的 URL 与主标题 |

**禁止：**

- 「先上线占坑，SEO 以后再说」  
- 同一 URL 短期内反复大改 title/H1「试关键词」  
- 功能做完才发现 URL/意图错了再整页推翻（视为违反本条） |

**允许的例外（须在提交说明写明原因）：** 合规紧急修复；事实错误；法律要求；数据源/署名更正。纯「换个更好听的标题」不算例外，应在上线前用 R1 一次定稿。

---

### R2 — 内容上线一律「专家全面测试模式」

任何面向客户的页面/文案/工具逻辑，上线前必须完成专家级全面测试，禁止「本地扫一眼就 push」。

**全面测试最低清单：**

| 层 | 测什么 |
|----|--------|
| 功能 | 主流程可走通（生成 → 勾选 → Compare → Hot Pick）；边界（0 选、超选、换筛选） |
| 文案逻辑 | 分数含义清晰；Hot Pick 理由与决策逻辑一致；娱乐层不伪装成「定名判决」 |
| SEO/分享 | title、description、canonical、og 与页面一致 |
| 合规 | Fortune / 广告 / 联盟免责齐全；开源署名在需要处可见 |
| 设备 | 桌面 + 手机主流程；无横向撑破、无点不到按钮 |
| 性能 | 无整页无谓重载；无重 3D/大动画拖垮加载（广告站底线） |
| 回归 | `npm run build` 通过；关键路由无被 `_redirects` 误伤 |

**未过测试 = 不上线。** 可用简短测试记录留在 PR/提交说明，**不要**把测试记录页面挂到正式站。

---

### R3 — 站上只放面向客户的内容

| 可以上站 | 禁止上站 |
|----------|----------|
| 产品说明、操作提示、结果解释 | Cursor/豆包/内部讨论原文 |
| 合规 Disclosure / Privacy | 「按 NAMING-LAB-PLAN」「Phase 1」「待办」 |
| 开源数据署名（客户可读的短句 + 链接） | 完整内部指令、报价策略、竞品阴私话术 |
| 英文为主的客户 UI（美式市场） | 中文运营备忘当正文（除非明确做中文市场页） |

内部文档只放 `docs/`（及本地笔记），**默认不进 `src/pages` 可访问路由。**

## 2. 建议一并生效的规则

### R4 — 品牌与仓库边界

| 站 | 做什么 |
|----|--------|
| **HotPick Lab**（本仓库） | Naming Lab：选名 / Compare / Hot Pick / 娱乐 Fortune；广告变现 |
| **MiniTool HQ** | 卖家工具：压缩、HEIC、箱规、格式转换等 |

**禁止：** 两边共用产品功能、共用 AdSense 账号策略混站、互相塞入口当主业。

---

### R5 — 数据与算法：不闭门造车

- 优先 `docs/DATA-SOURCES.md` 中的 **公开/开源、可署名** 数据与代码。  
- 新词库/牌意/频率：用 `npm run build-naming-data`（或同等流水线）生成，并更新 `src/data/naming/ATTRIBUTION.md`。  
- **禁止**把竞品整库扒镜；AKC/Rover 等仅可用公开 Top 作趋势标签。  
- 自写启发式（如 vibe 标签）允许，但须在内部文档标明「启发式，非第三方专有库」。

---

### R6 — Fortune Draw（塔牌）产品尺度

- 性质：**Entertainment / Fun vibe**，文案固定含 *Fun reading · Not a prediction*（或同等英文）。  
- **不决定** Hot Pick 胜负；实用分 / 明确规则决定精选。  
- UI：**轻量**；可折叠或弱展示；禁止重动效塔盘/3D。  
- 「塔盘」若指分层展示：仅扁平卡片分区，服务停留与广告位，不替代工具逻辑。

---

### R7 — 变现与合规

- 广告不挡主流程（生成 / Compare / 翻牌）。  
- AdSense/联盟未批前：可用占位，**不伪造**「已投放」话术。  
- 需要时的 Disclosure、Privacy 保持可访问且与真实产品一致。  
- **禁止**自点联盟链接测流量；禁止彩票类、硬算命承诺等广告高风险玩法。

---

### R8 — 语言与市场（v1）

- 客户 UI / SEO 正文：**美式英文为主**。  
- 内部沟通可用中文；上站前须译成客户英文（或经确认的双语策略）。  
- 日/中/欧本地语起名：按计划「以后再说」，不擅自做进 v1 主路径。

---

### R9 — 发布与协作流程

1. 改代码 / 文案 → 对照 R1（若涉 SEO）+ R2 测试  
2. `npm run build` 通过  
3. 提交说明写清 **为什么**（客户价值），不写内部争吵过程  
4. Push / 部署后：sitemap + 重点 URL 通知索引（如适用）  
5. 用 Cloudflare **Unique visitors** + 站长工具看效果；不把爬虫当真人业绩  

**Cursor 协作：** 用户说「按 OPERATING-RULES」或「按 NAMING-LAB-PLAN」时，代理须同时遵守本文 + 对应策划文档。

---

### R10 — 范围控制（不做清单）

本站 v1 **不做**（除非书面改计划）：

- MiniTool 类工具迁入  
- Logo SaaS、登录墙、次数墙优先  
- 真商标查询 API、真算命/时辰定名主流程  
- 为视觉毁掉性能的重塔盘动效  

---

## 3. 上线门禁（一页核对）

发布前打勾：

- [ ] R1 + **R1b** SEO 在立项/建页时已一次按专家模式定好（非事后补救）
- [ ] R2 功能 / 文案逻辑 / 移动端 / build 已测
- [ ] R3 无内部指令、无中文备忘残留在客户可见 UI
- [ ] R5 数据源与署名仍正确（若动过命名数据）
- [ ] R6 Fortune 不抢 Hot Pick 决策（若页面含翻牌）
- [ ] R4 未误加 MiniTool 功能
